# Dynamic Ledge for Windows — privacy

Effective 4 November 2026, starting with Windows version 0.5.2. Manufacturer model reporting starts with 0.5.3. Update source, failed update steps and unclean-quit reports start with 0.5.4. This policy also covers the Microsoft Store edition.

Dynamic Ledge does not require an account. Notes, tasks, preferences and pinned references stay in your Windows user folder. Unpinned clipboard history stays in memory. If you enable Text from copied images, Windows recognizes the text on your device; Dynamic Ledge keeps only the text as a regular clip and discards the image. The optional Codex approval mode reads the waiting session’s local transcript to dismiss the card; it does not save or send transcript content. Original files are not uploaded by the tray; choosing Windows sharing sends selected items to the recipient or app you choose.

## App analytics

Dynamic Ledge sends a small set of lifecycle and update events to [TelemetryDeck](https://telemetrydeck.com/): first launch of a new installation, app launches, daily activity, first launch of a newer version, update availability, update attempts and categorized update/check failures. Analytics is enabled without an in-app switch. There is no screen recording or feature-by-feature activity tracking.

Each event contains its event name and time, app version, Windows 10 or 11, x64 or ARM64 architecture, the shared manufacturer computer model (such as Surface Laptop 5), and whether the copy was installed from Microsoft Store, Scoop or a portable ZIP. The model is read once in the background from Windows' manufacturer model property; it is not your custom computer name or a unique device identifier. Missing or invalid model information is reported as Unknown. Update events may include the previous or target app version, a broad failure category such as network, invalid release or installation, the update step that failed, and for failures inside the app the error's type name (such as IOException). An update event can also say whether it started automatically, from the app, or another way such as Scoop or a ZIP. If the app ended without quitting, the next launch reports that it happened and the version that was running. Crash logs and raw error messages are never read or sent.

A random identifier is created in the app's local data folder and hashed with SHA-256 before sending. It is not derived from your name, email, Windows account, hardware identifiers or account credentials. TelemetryDeck further salts and hashes that value. This identifier lets us count participating installations over time; it does not identify a person, and one person using several PCs may count several times. A daily session identifier and a random event identifier support grouping and duplicate analysis.

Event payloads contain no names, email addresses, device names, hardware serial numbers, clipboard contents, notes, file names or paths, calendar details, URLs you visit, account details, coding prompts, approval commands or media titles. The app does not attach an IP address or location to events. As with any internet connection, TelemetryDeck receives network connection information while accepting requests; its handling is described in [TelemetryDeck's privacy policy](https://telemetrydeck.com/privacy/). No claim is made that network transport hides your IP address from the receiving service.

Unsent events are kept locally for up to seven days, with a maximum of 64 events, and removed locally after the server acknowledges them. Sending uses an eight-second timeout and backoff after failures. Reports can include retries or gaps after a crash or prolonged offline use. Update success means a newer version actually launched, rather than only being downloaded. Daily activity means the app was running during an unlocked Windows session; it is not a measurement of continuous interaction.

Deleting the app's local analytics state resets its random identifier; it does not erase already aggregated remote reports and the next launch creates a new identifier. Uninstalling or blocking network access stops further events. Download counts from GitHub are separate from app analytics and include repeat downloads, updates and automated requests.

## Optional connections

Microsoft Store manages updates for the Store edition. Update checks in the Scoop and portable editions contact the official GitHub release repository. Calendar subscriptions contact the source you configure. Optional lyrics lookup sends track and artist metadata to LRCLIB. Optional coding-tool usage connections query local tools; they are separate from product analytics. Camera preview starts only when requested and stops when closed or the session locks. Windows manages camera permissions. The optional browser extension bridge is available with the website edition. Browser download integration and coding hooks operate only when configured.

For privacy questions, contact the publisher through the official [Talvioh website](https://talvioh.vercel.app/contact.html). This policy covers the Windows app; other services have their own policies.
